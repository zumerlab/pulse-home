# Pulse for Home Assistant (`pulse-home`)

Pulse's product for Home Assistant: the standalone app, the `zumer-pulse` custom card and the `zumer-pulse` dashboard and section strategies, over a live Home Assistant or the six demo homes. The UI itself, the radial object with layers by urgency, is `@zumer/pulse`, the core, in its own repo at `../pulse`; the core knows nothing about Home Assistant, this repo knows nothing about how the object draws. What is UI of the object goes in the core; what is about Home Assistant goes here. Pulse's other sources (a machine, the world, a boat, fleets, drones, the sky, the station, cameras) live in `../pulse-apps`, private.

- **The core comes in as a dependency, read live from the checkout beside**: `vite.shared.ts` aliases `@zumer/pulse` to `../pulse/src` when that checkout exists (and dedupes Orbit, Zumly and hls.js onto this repo's copies; `withCore` wraps both Vite configs), `tsconfig.json` `paths` the same, so a change in the core is live here at once; without the checkout, the npm package (`@zumer/pulse` in `package.json` with the range `npm install` writes; after each publish of the core, `npm install @zumer/pulse@latest` here). Run `npm install` here again when the core changes its dependencies. Import the core as `@zumer/pulse`, never by relative path.
- **Files**: `src/` is Vite's root, with the pages (`index.html` the app, `gallery.html` the index of demo homes, `card.html` the card's bench: served in development, left out of the build) and the code: `model.ts` (the systems of a home from the entity, device and area registries: lights, climate (with the `weather` entity and `sun.sun`, the wind and the sun as bearings), security (each camera an object of its own, `cameraObject`; a lock with a `code_format` asks for the code), people (`person` and the `device_tracker`s no person follows, who is home and a map around `zone.home`, each person an object, `personObject`), openings, media, energy, scenes, maintenance (with HA's persistent notifications as `Registry.notices`, a row each, a tap dismisses) and Assist (`whole: true`: about the home as a whole, kept whatever areas are chosen; `PulseSource.ask` is `conversation/process`, the answers kept in `assist`, the questions every home understands on a choice ring and the viewer's own words through the keypad's `'words'` format); `roomSystems` builds the rooms axis, each area an object with the systems' channels read within it), `source.ts` (the `PulseSource` interface and its WebSocket implementation: states, registries, services, history, notices, `ask`), `host.ts` (binds them to the core's `PulseHost`), `app.ts` (`mountPulse`, options `systems/areas/mode/start/settings/look`; the gear lets the viewer choose within them, kept in `localStorage`), `main.ts` (the standalone shell, URL parameters), `login.ts` (sign-in with HA's own OAuth flow; the chosen demo home previewed beside the form, `preview.ts`), `gallery.ts` (the index of demo homes), `strings.ts` (this app's words; the core's are in its `i18n.ts`), `style.css`, `card/` (`zumer-pulse.ts`: the card and both strategies in one module, `npm run build:card` → `dist-card/zumer-pulse.js`, about 810 kB / 190 kB gzip; `hass-source.ts` reads the dashboard's `hass`; the Zumer prefix because other HA cards already use "pulse"), `hls-none.ts` (what both Vite configs alias `hls.js` to: HA's cameras are stills or MJPEG, the video stack stays out), `card-bench.ts` (the card over a demo home, no HA needed; what the tests use), `demo/` (the six homes of demo.home-assistant.io as a `PulseSource`, ported from `home-assistant/frontend`, Apache 2.0, `src/demo/NOTICE.md`; regenerate with `src/demo/scripts/import-homes.py <frontend checkout>`, `--check` compares; never edit the data by hand). At the root: `scripts/` (`ha-tokens.mjs`, `ha-install-card.mjs`, `ha-check-card.mjs`), `tests/` (`ha.spec.ts` over the demo homes, `ha-live.spec.ts` against a live HA), `docs/images/` (the README's pictures), the configs. Nothing else loose at the root (Martin, 07/11).
- **Docs**: `README.md` is the front door for Home Assistant users, and what the Marketplace shows (`render_readme`): practical and complete, what it shows, requirements, install from the Marketplace or by hand, the four ways to use it, the options, the settings, the views, what each system reads and when an alert fires, troubleshooting; plain words, no phrases that say nothing (Martin, 07/11). Keep its tables current when the card changes. `DEVELOPMENT.md` the developer's notes, `docs/home-assistant-integration.md` the integration plan, `hacs.json` the Marketplace manifest (the release must carry `zumer-pulse.js`).
- **Test Home Assistant**: local Docker at `127.0.0.1:8123`. The app signs in with Home Assistant's own OAuth flow in the browser (Martin signs in; never type his credentials). For an automated live check, `.env.local` (gitignored, not read by the app) has `HA_URL/HA_USERNAME/HA_PASSWORD`: `scripts/ha-tokens.mjs .env.local <tokens.json>` runs HA's login flow with them; the live test seeds `localStorage['pulse-ha-auth']` with the tokens. To check the card inside the local HA: `npm run dev`, then `scripts/ha-tokens.mjs` + `scripts/ha-install-card.mjs` register the dev server's `dist-card/zumer-pulse.js` (new `?v=` each time) as a resource and the `pulse-demo` / `pulse-sections` dashboards; HA's own frontend can be opened in Playwright by seeding `localStorage['hassTokens']` with those tokens (again: never type credentials); `scripts/ha-check-card.mjs <tokens.json> <out dir>` does that for both dashboards and the editor, with screenshots.
- **Checks**: `npm run typecheck`, `npm run lint`, `npm test` (Playwright starts the app on 5174 and runs it over the demo homes, `?demo=home`, no HA needed; `PULSE_HA_TOKENS=<tokens.json> npx playwright test tests/ha-live.spec.ts` adds one run against the live HA). `npm run dev` (5174; the gallery at `/gallery.html`, the bench at `/card.html`), `npm run build`, `npm run build:card`. After changing a dependency version add `-- --force`. The camera test loads an image from brands.home-assistant.io: it fails where that host is blocked.
