# Pulse for Home Assistant (`pulse-home`)

Pulse's product for Home Assistant: the standalone app, the `zumer-pulse` custom card and the `zumer-pulse` dashboard and section strategies, over a live Home Assistant or the six demo homes. The UI itself, the radial object with layers by urgency, is `@zumer/pulse`, the core, in its own repo at `../pulse`; the core knows nothing about Home Assistant, this repo knows nothing about how the object draws. What is UI of the object goes in the core; what is about Home Assistant goes here. Pulse's other sources (a machine, the world, a boat, fleets, drones, the sky, the station, cameras) live in `../pulse-apps`, private.

- **The core comes in as a link**: `"@zumer/pulse": "file:../pulse/packages/core"` while it is not on npm, so a change in the core is live here at once (`vite.shared.ts`: Vite serves the core from where it really is and dedupes Orbit, Zumly and hls.js onto this repo's copies; `withCore` wraps both Vite configs). Run `npm install` here again when the core changes its dependencies. When the core is published, the link becomes a pinned version. Import the core as `@zumer/pulse`, never by relative path.
- **Files**: `model.ts` (the systems of a home from the entity, device and area registries: lights, climate (with the `weather` entity and `sun.sun`, the wind and the sun as bearings), security (each camera an object of its own, `cameraObject`; a lock with a `code_format` asks for the code), people (`person` and the `device_tracker`s no person follows, who is home and a map around `zone.home`, each person an object, `personObject`), openings, media, energy, scenes, maintenance (with HA's persistent notifications as `Registry.notices`, a row each, a tap dismisses) and Assist (`whole: true`: about the home as a whole, kept whatever areas are chosen; `PulseSource.ask` is `conversation/process`, the answers kept in `assist`, the questions every home understands on a choice ring and the viewer's own words through the keypad's `'words'` format); `roomSystems` builds the rooms axis, each area an object with the systems' channels read within it), `source.ts` (the `PulseSource` interface and its WebSocket implementation: states, registries, services, history, notices, `ask`), `host.ts` (binds them to the core's `PulseHost`), `app.ts` (`mountPulse`, options `systems/areas/mode/start/settings/look`; the gear lets the viewer choose within them, kept in `localStorage`), `main.ts` (the standalone shell, URL parameters), `login.ts` (sign-in with HA's own OAuth flow; the chosen demo home previewed beside the form, `preview.ts`), `gallery.ts` (the index of demo homes), `strings.ts` (this app's words; the core's are in its `i18n.ts`), `style.css`, `card/` (`zumer-pulse.ts`: the card and both strategies in one module, `npm run build:card` → `dist-card/zumer-pulse.js`, about 810 kB / 190 kB gzip; `hass-source.ts` reads the dashboard's `hass`; the Zumer prefix because other HA cards already use "pulse"), `hls-none.ts` (what both Vite configs alias `hls.js` to: HA's cameras are stills or MJPEG, the video stack stays out), `card.html` + `card-bench.ts` (the card over a demo home, no HA needed; what the tests use), `demo/` (the six homes of demo.home-assistant.io as a `PulseSource`, ported from `home-assistant/frontend`, Apache 2.0, `demo/NOTICE.md`; regenerate with `demo/scripts/import-homes.py <frontend checkout>`, `--check` compares; never edit the data by hand), `scripts/` (`ha-tokens.mjs`, `ha-install-card.mjs`, `ha-check-card.mjs`), `tests/` (`ha.spec.ts` over the demo homes, `ha-live.spec.ts` against a live HA), `images/` (the README's pictures).
- **Docs**: `README.md` is the plain-language front door for HA users (why Pulse, where it comes from, install from the Marketplace or by hand, the four ways to use it: no jargon, no option tables; keep it that way), `card/README.md` the reference (options, entities, alerts, troubleshooting; keep it current when the card changes), `DEVELOPMENT.md` the developer's notes, `docs/home-assistant-integration.md` the integration plan, `hacs.json` the Marketplace manifest (the release must carry `zumer-pulse.js`).
- **Test Home Assistant**: local Docker at `127.0.0.1:8123`. The app signs in with Home Assistant's own OAuth flow in the browser (Martin signs in; never type his credentials). For an automated live check, `.env.local` (gitignored, not read by the app) has `HA_URL/HA_USERNAME/HA_PASSWORD`: `scripts/ha-tokens.mjs .env.local <tokens.json>` runs HA's login flow with them; the live test seeds `localStorage['pulse-ha-auth']` with the tokens. To check the card inside the local HA: `npm run dev`, then `scripts/ha-tokens.mjs` + `scripts/ha-install-card.mjs` register the dev server's `dist-card/zumer-pulse.js` (new `?v=` each time) as a resource and the `pulse-demo` / `pulse-sections` dashboards; HA's own frontend can be opened in Playwright by seeding `localStorage['hassTokens']` with those tokens (again: never type credentials); `scripts/ha-check-card.mjs <tokens.json> <out dir>` does that for both dashboards and the editor, with screenshots.
- **Checks**: `npm run typecheck`, `npm run lint`, `npm test` (Playwright starts the app on 5174 and runs it over the demo homes, `?demo=home`, no HA needed; `PULSE_HA_TOKENS=<tokens.json> npx playwright test tests/ha-live.spec.ts` adds one run against the live HA). `npm run dev` (5174; the gallery at `/gallery.html`, the bench at `/card.html`), `npm run build`, `npm run build:card`. After changing a dependency version add `-- --force`. The camera test loads an image from brands.home-assistant.io: it fails where that host is blocked.
- Everything in this repo is in English: code, comments, identifiers, commits, docs and UI strings. Chat with Martin stays in Spanish; the notes in `../coordinacion/` stay in Spanish.
- If a workaround shows up for something that belongs to the core, Orbit or Zumly: do not leave it hidden here. Fix it there, or note it in `../coordinacion/PENDIENTES.md` under that project.
- Orbit (`@zumer/orbit` 2.2.0) and Zumly (1.2.2) come from npm. To try an unpublished branch, it goes in as a `.tgz` in `vendor/`: `../coordinacion/README.md`.
